## Story (context, not binding)
As an assistant working in any project generated from this template, I want
`CLAUDE.md` to state plainly that Workflow Guardian's rules apply
automatically to task-branch/requirements/TDD work — and that I may use
`make` targets, the `butler` CLI, or the `butler-mcp` MCP server
interchangeably to carry them out — so that I stop treating the referenced
agent file as optional background reading I can skip past invocation, and
never fall back to a raw `git`/`gh` command just because one specific
interface (e.g. `make`) wasn't explicitly named.

## Description
**Motivation (observed live, 2026-07-31, this repo, python-butler
itself):** While working directly in this repo's main conversation (not
via an explicit `@workflow-guardian` invocation), the following gates from
`.claude/agents/workflow-guardian.agent.md` were skipped: a task file was
committed with a raw `git commit -m "..."` instead of a `make`/`butler`
target (violates the agent's "Commit via Makefile gate" /
`commit-workflow` skill), and the GitHub Projects draft-stage sync
(`butler task sync-project <ID> --stage draft`, mandated immediately after
committing a new task file per the agent's "GitHub Projects draft sync
gate") was not run until the user asked why the board item was missing.
Root-caused to reading `git log` for a plausible-looking pattern instead of
consulting the agent file / `commit-workflow` skill directly — both gates
were fully documented and available the whole time.

`templates/CLAUDE.md.tmpl` is the generated-CLAUDE.md source every
consumer project (and this repo's own conceptual "self-hosting" case)
inherits; its "Task Management" section currently only *references* the
Workflow Guardian agent file, without stating that its rules are a standing
constraint rather than optional guidance triggered by explicit invocation.

**Fix:** Per Requirement 10, add to `templates/CLAUDE.md.tmpl`'s "Task
Management" section (the paragraph that already names
`{{WORKFLOW_GUARDIAN_NAME}}`):

1. A sentence stating `{{WORKFLOW_GUARDIAN_NAME}}`'s rules apply
   automatically to any task-branch/requirements/TDD work in the repo,
   independent of whether the agent is explicitly `@`-mentioned.
2. A sentence stating the underlying operations (branch/stage/commit/pr/
   merge, task-file sync) may be performed via the `make` targets, the
   `butler` CLI, or the `butler-mcp` MCP server interchangeably — the
   constraint is on never bypassing all three with a raw `git`/`gh`
   command, not on which of the three is used.

The existing `Task workflow` code block (the `make branch-task` / ...
example) MAY stay `make`-flavored as the concrete illustration, since the
new prose sentence already generalizes to the other two interfaces.

**Second file, outside this repo:** the user's personal global
`~/.claude/CLAUDE.md` (not part of this repo, not generated by
`generate-governance-files`; hand-maintained, currently a near-copy of an
older version of this template) gets the equivalent wording change applied
directly, as a courtesy step of this task, even though it is not tracked
by this repo's git history and therefore has no Branch/Stage/Commit steps
of its own below.
